# Smart Home ІКС

Інтелектуальна система керування мікрокліматом і енергоощадженням розумного будинку.
Навчальний проєкт з дисципліни «Інтелектуальні комп'ютерні системи», виконує Кодовбецька В. І., група ІАВ-21.

## Присутність людей

Присутність визначається карткою-ключем (`Картка.вставлена`), а датчик руху працює на охорону:
рух без картки → тварина, можливе проникнення (сигналізація) або вітер/штора при відкритому вікні.

## Структура

```
data/            база знань
  rules.json         27 правил (24 + R26–R28 після ПР4): 19 з ПР3 (кожне з одним висновком) + 5 правил картки-ключа
  facts.json         база фактів з ПР2 у форматі «об'єкт – атрибут – значення»
  initial_state.json початковий стан пристроїв і режиму
  scenarios.json     тестові ситуації
  fuzzy_vars.json    лінгвістичні змінні та функції належності (ЛР2)
  rules_fuzzy.json   ті самі 27 правил з нечіткими умовами (ЛР2)
  scenarios_fuzzy.json  ситуації з невизначеністю (ЛР2)
  rules_ml.json      R25 «Прогноз перегріву», правило для гібридної системи (ЛР3)
  scenarios_ml.json  сценарії для гібридної системи (ЛР3)
  test_scenarios.json  17 тестових сценаріїв з очікуваними результатами (ПР4)
  v1/                база правил до адаптації (ПР4), для порівняння «до / після»
engine/          ядро rule-based системи (ЛР1)
  working_memory.py  робоча пам'ять
  rules.py           завантаження правил і перевірка умов
  inference.py       механізм виведення (прямий ланцюжок)
fuzzy/           нечітка логіка й коефіцієнти впевненості (ЛР2)
  membership.py      функції належності
  certainty.py       обчислення CF
  memory.py          робоча пам'ять з CF
  inference.py       виведення з невизначеністю
ml_service/      ML-сервіс прогнозу перегріву, REST API на Flask (ЛР3)
  generate_data.py   синтетичні навчальні дані (data/overheat.csv)
  train.py           навчання моделі RandomForest, метрики в models/metrics.json
  app.py             сервіс: GET /health, POST /predict
hybrid/          звернення ІКС до ML-сервісу (ЛР3)
  ml_client.py       запит до /predict і перетворення відповіді на факт з CF
analysis/        запуск тестових сценаріїв, перевірка суперечностей К1–К8, випадкові ситуації (ПР4)
tests/           unit-тести pytest (ЛР4)
.github/workflows/tests.yml  автоматичний запуск тестів на GitHub Actions (ЛР4)
logs/            журнал роботи ics.log (створюється під час запуску, не в git)
main.py          запуск ЛР1
lr2.py           запуск ЛР2
lr3.py           запуск ЛР3 (гібридна система)
pr4.py           запуск ПР4 (тестування й адаптація бази правил)
ics_logging.py   налаштування журналу (ЛР4)
pytest.ini       налаштування pytest
.coveragerc      налаштування вимірювання покриття
requirements.txt бібліотеки для ЛР3, ЛР4 і графіків
plot_terms.py    графіки функцій належності (потрібен matplotlib)
reports/         звіти
```

## Запуск

Потрібен лише Python 3.10+ (сторонні бібліотеки не потрібні).

```
python main.py                 # усі сценарії
python main.py -s 3            # один сценарій
python main.py -s 3 --explain  # з поясненням, чому правила не спрацювали
python main.py -s 3 --explain R18,R21  # пояснення лише для вказаних правил
python main.py -f data/facts.json

python lr2.py                  # ЛР2, усі сценарії з невизначеністю
python lr2.py -s 2 --compare   # порівняння з чіткою системою ЛР1
```

На macOS замість `python` пишіть `python3`.

### ЛР3: гібридна система (правила + ML)

Для ЛР3 потрібні бібліотеки: `pip install -r requirements.txt`.

```
python3 ml_service/generate_data.py   # один раз: навчальні дані
python3 ml_service/train.py           # один раз: навчання моделі
python3 ml_service/app.py             # термінал 1: сервіс на http://127.0.0.1:8000
python3 lr3.py                        # термінал 2: усі сценарії
python3 lr3.py -s 1                   # один сценарій
```

Модель прогнозує ймовірність того, що за 30 хв у кімнаті стане понад 26 °C.
Ймовірність стає фактом `Прогноз.перегрів` з CF, правило R25 використовує цей факт,
і його висновок поєднується з висновками правил за формулою MYCIN з ЛР2.
Якщо сервіс не запущено, система попереджає і працює лише на правилах.

### ПР4: тестування й адаптація

```
python3 pr4.py                 # 17 тестових сценаріїв: база v1 (до) і v2 (після адаптації)
python3 pr4.py -t T6           # один тест докладно
python3 pr4.py --random 2000   # випадкові ситуації, пошук суперечливих станів К1–К8
```

### ЛР4: тести, покриття, журнал

Потрібні pytest і pytest-cov: `pip install -r requirements.txt`.

```
python3 -m pytest                          # усі тести
python3 -m pytest --cov                    # з підсумком покриття
python3 -m pytest --cov --cov-report=html  # звіт у htmlcov/index.html
```

Журнал роботи пишеться в `logs/ics.log`. У `main.py`, `lr2.py`, `lr3.py` і `pr4.py`
рівень деталізації задає ключ `--log-level`, наприклад `python3 main.py -s 3 --log-level DEBUG`.

### Графік функцій належності

Для `plot_terms.py` потрібен matplotlib. Графік зберігається в `reports/terms.png`.

```
pip install matplotlib
python3 plot_terms.py
```

На macOS, якщо matplotlib встановлено у віртуальне середовище, спершу активуйте його:
`source .venv/bin/activate`
